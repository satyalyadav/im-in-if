# Domain docs

This repo uses one domain context, with `GLOSSARY.md` at
the root and decisions in `docs/adr/`.

Before exploring the project, read `GLOSSARY.md` and the
ADRs relevant to the task. Preserve their existing contents.

Use glossary terms in issues, code, tests, and explanations.
If a needed term is missing, note the gap for domain modeling.

Call out any proposed conflict with an ADR explicitly.
If a domain document is missing, proceed silently.
